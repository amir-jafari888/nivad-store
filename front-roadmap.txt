# 1. اتصال کامل Design به Root و setting.css

تمام Frontend باید از یک Design Source of Truth استفاده کند.

مرجع اصلی:

```text
:root
[data-theme="light"]
[data-theme="dark"]
```

و تمام Tokenهای اصلی در:

```text
assets/css/setting.css
```

مدیریت می‌شوند.

هیچ Phaseای نباید برای رنگ، Radius، Shadow، Spacing، Typography، Gradient، Transition یا Animation مقدارهای پراکنده و بی‌دلیل ایجاد کند.

# 7. No Polish Phase

هیچ Phase جداگانه‌ای برای:

```text
Polish
Beautification
Final Styling
Redesign
```

وجود ندارد.

تمام کیفیت مورد نیاز باید هنگام Design همان Phase حل شود.

اگر بعداً Defect واقعی پیدا شود، فقط همان Defect طبق Audit اصلاح می‌شود.

---

# 8. Batch Rule

هر Phase در زمان اجرا به Batch تقسیم می‌شود.

هر Batch:

```text
10 Steps
```

دقیقاً.

ساختار:

```text
AUDIT
→ IMPLEMENT
→ TEST
→ REGRESSION
→ PASS
→ LOCK
→ NEXT BATCH
```

اگر حتی یک Test Fail شود:

```text
BATCH FAIL
LOCK = NO
```

---

# 9. Frontend Backend Freeze

Backend فعلاً Freeze است.

Frontend نباید صرفاً به دلیل یک Feature جدید، Backend را تغییر دهد.

اگر قابلیت جدید به Backend نیاز داشته باشد:

```text
Frontend Ready
Backend Dependency = Documented
```

و تغییر Backend تا زمان مناسب به تعویق می‌افتد.
